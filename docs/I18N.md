# Masta-Octa UI internationalization (i18n)

## Approach

The desktop app uses a **TypeScript message catalog** with a typed `t(key, vars?)` helper and
`LocaleProvider`. We deliberately **do not** add i18next or other runtime i18n npm packages:
messages are static objects, parity is enforced in tests and typecheck, and the bundle stays
small.

Persistence follows the same pattern as themes: `localStorage` key `masterocta.ui-locale`,
best-effort writes, default **`ja`** when missing or invalid. `main.tsx` calls
`applyStoredLocaleBeforePaint()` before the first paint and sets `document.documentElement.lang`.
Language changes use `startTransition` and **do not** call `location.reload()`.

## Adding strings

1. Add the key and English copy to `src/i18n/messages/en.ts`.
2. Add the **same key** and Japanese copy to `src/i18n/messages/ja.ts` (`satisfies Record<MessageKey, string>`).
3. If the string uses `{placeholders}`, extend `MessageParams` in `src/i18n/messages/index.ts`.
4. Use `useTranslate()` in components: `t('your.key', { count: 1 })`.
5. Prefer **full sentences** per key; do not concatenate translated fragments in the UI.
6. Never use translated labels as React keys, API values, or internal state identifiers.
7. User-visible file names and Octatrack paths stay literal; only chrome is translated.
8. Do **not** use `dangerouslySetInnerHTML` for translated text.

Unknown keys fall back to English at runtime (with the key name kept for diagnosis).

## Errors

Backend / IPC `Error.message` strings stay as returned. Map known validation cases to stable
**codes** (for example waveform range empty / beyond file / preview limit) and translate via
`t()` in the UI. Unknown errors show a generic message plus diagnostic detail in a separate node.

## Tests

- `src/i18n/messages.test.ts` — ja/en key and placeholder parity.
- Component tests: import `tJa` / `tEn` from `src/i18n/testStrings.ts` for labels and aria text.
- E2E: `e2e/i18n.ts` `uiText(locale, key, vars?)` so locators track the catalog (default UI locale is ja).

## Scope (MO-UI-I18N-LIBRARY-1)

**Translated in this wave:** AppShell context bar, Sources, Library browse (catalog browser,
AudioLibrary, ProjectWorkspace), Inspector shell, manual tags/notes, Waveform preview (loading,
errors, range playback UI), legacy write restriction notice, span duration labels.

**MO-UI-OPERATIONS-DRAWER-1:** Operations Drawer chrome (`operations.*`, `workspace.openOperations*`, status continuation/recovery/unavailable). Clone/Rename/Copy **panel bodies** remain English until a dedicated operator i18n wave. Locale changes must not reset drawer workflow state or re-run waveform IPC.

**MO-UI-SLICE-WORKSPACE-1:** Inspector slice tab expand/exit chrome (`inspector.expandSliceWorkspace*`, `inspector.exitSliceWorkspace*`). Slice editor body (zoom, marker table, hints) remains English. Expand/collapse and locale changes must not reset slice session state or re-run draft/proposal/waveform IPC.

**Not translated yet:** Clone / Rename / Change Drawer operator panel bodies (detailed steps), Slice workbench (full UI), Usage Graph
row formatting, Home legacy Scan/Browse/project search, legacy ProjectDetail / Audio Pool / Tools,
Docusaurus user-guide.

## Waveform / locale

Changing locale must **not** re-run waveform IPC. `WaveformPreview` query effects depend on
`[api, assetId, rootId, debouncedTargetPoints, debouncedViewport]` (plot width + zoom/pan
viewport), not on `t` or locale. Locale changes must **not** reset viewport, selection, or
playback state.

**MO-M7-RANGE-TO-SLICE-ANALYSIS-1:** Attack slicing paths touched by Library range handoff use `slicing.*` keys (analyze selected range, analysis region label, structured errors). Remaining slice editor chrome (zoom, marker table, hints) stays English until a follow-up.

**MO-UI-SLICE-RANGE-HANDOFF-FIX-1:** `slicing.previewSelectionHeading`, `slicing.previewSelectionNone`, `slicing.previewSelectionSeconds`; updated `slicing.regionHelp` (manual vs preview). Locale changes must not reset range state or re-run analysis IPC.

**MO-M7-RANGE-TO-SLICE-REVIEW-FIX-1:** Slice workbench stores normalized IPC errors (code + optional backend `message`) in state and derives translated summaries at render time. `INVALID_SLICE_REQUEST` is a broad bucket: the UI uses `slicing.error.genericDetail` with the backend `message` (English diagnostic text) instead of the generic `slicing.error.INVALID_SLICE_REQUEST` string alone. Locale changes must not re-run draft/proposal/waveform IPC. Library waveform `stopPlaybackToken` invalidates in-flight range preview create/read without backend cancel.

**MO-SLICE-ANALYSIS-SESSION-RECOVERY-1:** `slicing.reanalyzeRequired` and `slicing.error.ANALYSIS_EXPIRED`. `ANALYSIS_NOT_FOUND` copy is unchanged (missing / cancelled / replaced job, and preview-token expiry). TTL-only job expiry uses `ANALYSIS_EXPIRED`. Locale changes must not clear an invalid-session banner, reset the in-memory draft, or re-run analysis IPC. Do not auto-reanalyze or auto-apply candidates.

Waveform zoom/pan/drag strings live under `waveform.zoom*`, `waveform.pan*`,
`waveform.fitSelection`, `waveform.interactionHint`, and `waveform.viewportFrames`.

## MO-UI-WORKSPACE-FIX-2

**Library geometry → Slice handoff:** `WaveformPreview` notifies committed geometry with
`rootId`, `fileInstanceId`, `assetId`, and a selection generation. Parent panels store that
binding and pass `librarySelectionRange` to `SliceWorkbench` only when the binding matches
the current selection. Stale notifications from a previous asset are ignored; selection changes
invalidate stored range until the new waveform commits.

**Narrow layout:** Breakpoint `(max-width: 840px)` is evaluated once in `RootRegistryPanel` and
passed to `AppShell` as `narrowLayout`. CSS display modes use React-assigned classes under
`.mo-app-shell--narrow`, not standalone layout `@media` rules in `AppShell.css`. Locale or pane
toggle must not re-run waveform IPC (unchanged).

**Inspector controls:** Top context bar buttons switch list vs inspector view
(`workspace.showInspector` / `workspace.showList`). The status bar “show inspector” control
uses the same visible label but `workspace.showInspectorStatusAria` for `aria-label` — it is
the recovery path when the sample list is full screen on narrow layout. While inspector is
full screen on narrow layout, the status bar “show sample list” control uses
`workspace.showListStatusAria` for `aria-label`. Narrow Sources navigation uses the existing
`Drawer` with `workspace.sourcesDrawerCloseAria` for the close control.

## MO-UI-LIBRARY-INSPECTOR-MIGRATION-1

**Inspector tabs:** Preview / Slice / Info / Usage / Notes use `inspector.tab*` and
`inspector.info*` keys. All five panels stay mounted for the selected asset; inactive panels use
`hidden`, `aria-hidden`, and `inert`. Tab changes must not re-run waveform IPC.

**Waveform hidden layout:** `WaveformPreview` accepts `layoutVisible`. When the Preview tab is
hidden, plot width is frozen so `v2_audio_waveform_query` is not reissued for zero-width layout.

**List chrome:** Column headers and off-page selection use `library.column*` and
`library.selectionOffPage`. Catalog refresh status uses `library.fileListRefreshing` /
`library.fileListLoadFailed` without clearing the current snapshot rows.

**Activity strip:** `inspector.activity*` and existing `waveform.stop` / `slicing.cancelAnalysis`
reach playback stop (`stopPlaybackToken` stops range playback and pauses the head preview)
and slice job cancel (registered cancel callback only). Catalog list refresh copy
(`library.fileListRefreshing` / `library.fileListLoadFailed`) is bound only to
`refreshLibrary()`, not panel-wide busy/error.

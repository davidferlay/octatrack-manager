## 2. Workspace height fallback (old WebView)

`tauri.conf.json` `minimumSystemVersion` is `10.13`. That is **not** a whole-app 10.13 guarantee. This change only keeps catalog workspace height parsing if `dvh` / `clamp()` / `min()` are unknown.

Unguarded (must parse):

```css
height: calc(100vh - 18rem);
max-height: calc(100vh - 8rem);
min-height: 12rem;
```

Later `@supports` apply `100dvh` and `clamp(...)` on current WebKit/Chromium (FIX-3 short-window behavior).

Expanded inspector reclaim uses class `mo-app-shell__inner-split--slice-expanded` from [`AppShell.tsx`](../src/app/AppShell.tsx) (`sliceWorkspaceExpanded` prop). `:has()` is not required. Expanded slice grid stays 1 column unless `@container slice-expanded (min-width: 40rem)` applies.

**Verification method and limits:**

- Source test: `pnpm run test:workspace-css` (`scripts/app-shell-workspace-css.test.mjs`) — first unguarded rule has no `dvh`/`clamp`/`min`/`max`; no `:has(.root-registry-slice-workspace)`.
- This is **not** a CSS parser from Safari 11. It checks the stylesheet text.
- Modern Chromium + Playwright WebKit: layout E2E (workspace height &gt; 160px at 1280×600, expand fills inner split, 1/2 columns).
- **macOS 10.13 device: NOT_RUN.** Playwright WebKit is not that OS.

Out of scope (still using `:has` / `@container` elsewhere): `PartsPanel.css`, `CatalogLibraryBrowser.css`. Not changed.
